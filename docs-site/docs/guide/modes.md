# 四种模式：Build / Plan / Auto / Target

输入框左侧的模式按钮点一下循环切换：BUILD → PLAN → AUTO → TARGET → BUILD。四种模式的区别是 AI 的**权限范围**与**终止方式**。

## BUILD（构建模式）

默认模式，功能完整。AI 可以写文件、改代码、执行构建命令，但每次需要授权的操作都会弹窗问你。

日常开发用这个。

## PLAN（计划模式）

进入这个模式后，AI 的写操作权限会被底层直接拦截禁用（工具层拦截，而非仅靠提示词约束）。AI 只能读取代码、检索文件并构思方案，无法修改任何文件或执行写操作命令。

适合这些场景：

- 你还不确定怎么改，想先让 AI 探索代码库、出个方案。
- 改动涉及多个文件或架构决策，想先看计划再决定。
- 你只想问问题、了解现有实现，完全不想它动手。

方案讨论清楚后切回 BUILD 再动手。

## AUTO（自动模式）

权限全放行。所有工具调用（写文件、执行命令、终端操作）自动批准，不弹任何授权窗。

::: danger 这个模式权限极大
只有灾难性删除（比如 `rm` 根目录或系统目录）仍会被拦截，其余一律放行。适合你已经清楚知道风险、希望 AI 全自动跑批量任务的场景。不熟悉的项目或者不确定 AI 会干什么的时候，别用这个。
:::

## TARGET（目标驱动模式）

权限与 AUTO 一致全放行，区别在于**有明确的终止条件**。进入 TARGET 时你需要描述一个目标声明，AI 会围绕这个目标自主规划并执行，直到以下任一情况终止并自动切回 BUILD：

- **目标达成**：AI 调用 `completeGoal` 声明完成，你在弹窗确认后退出。
- **连续失败**：连续多次工具调用失败达到阈值（默认 5 次）。
- **步数超限**：单次目标执行的工具调用次数达到上限（默认 50 步）。
- **手动中断**：你随时点按钮切到其他模式，已产生的检查点保留供回滚。

切到 TARGET 时会弹出目标输入框，填好目标后进入。与 AUTO 一样保留灾难性删除防护；与 AUTO 不同的是，AI 也能通过 `switchMode` 工具带 `goal` 参数主动进入 TARGET，而 AUTO 只能你手动进入。

阈值（最大步数、连续失败次数）可在设置页「目标驱动模式」分组里调整，适配不同复杂度的任务。

## AI 自己也能请求切换

除了你手动点按钮，AI 在规划清楚后也可以主动请求切换模式，你在界面上一键批准即可。比如它在 PLAN 模式下做完方案，会申请切到 BUILD 开始实施；它也能带目标声明申请切到 TARGET。

有两个方向上的限制：**AUTO 模式只能你自己手动进入**，AI 无法通过工具切进 AUTO。但反过来，处于 AUTO 模式时 AI 可以主动切到 PLAN——这是 AI 退出 AUTO 的唯一路径。TARGET 则可以由 AI 带 `goal` 参数主动进入，达成目标后调 `completeGoal` 退出。
