# 插件

::: warning 预览功能
插件功能正在分阶段开发。插件可以从本地 `.zip` 导入，也可以从插件商店安装，并提供**技能**、**子代理**、**工作区工具**、**槽位入口（设置页 / 侧栏 / 顶栏的 HTML 页面）**、**AI 工具**、**MCP 服务器**，以及**运行 hooks**（只读观察、工具/HTTP 请求改写，或全部 ASK 代审核，含高危）。AI 工具与 hooks 的业务逻辑在容器内的插件子进程中运行，不会进入 App 主进程；插件页面在 WebView 中运行，通过宿主接口读写文件。MCP 复用现有的 HTTP/stdio 链路。提供商第一版支持 OpenAI 兼容服务。
:::

插件是一个 `.zip` 包，可以一次性带来若干技能、子代理、工作区工具、槽位入口、AI 工具、MCP 服务器和 OpenAI 兼容提供商，以及在运行节点收到通知、在工具执行前后拦截或改写结果的运行 hooks，并由你统一启停和卸载。想自己做一个插件，见[插件开发](/advanced/plugin/)。

入口在「设置 → 插件」。

## 导入插件

1. 点右上角的导入按钮（＋），在文件选择器里选中插件的 `.zip` 文件。
2. 读取完成后弹出「安装插件」，显示名称、版本、发布者、简介，以及**将提供的内容**——与插件详情页一致，逐项列出图标、名称和说明。
3. 确认安装后，插件声明的贡献随启用生效；安装弹层不再逐项询问权限。
4. 点「安装」。装好后插件出现在列表里并立即生效（AI 的技能清单需要新开会话才会刷新，见下文）。

如果文件有问题，会弹窗逐条列出原因，什么都不会被安装；常见原因见本页末尾的〈出错怎么办〉。

## 插件商店

「设置 → 插件 → 插件商店」内置 AiCode 官方索引，始终保留，不能删除也不在设置里显示。点右上角齿轮打开「插件设置」，在「第三方插件源」里一行填一个索引地址（支持 `http://` 与 `https://`，指向 `index.json`）。商店会把所有来源的插件按来源顺序依次叠加：先官方索引的列表，再按输入行顺序拼接每个自定义来源，不单独切换来源。

同一「插件设置」里还可以填「镜像加速地址」：填一个 URL 前缀（例如 `https://gh-proxy.com/`）后，官方索引、GitHub 上的自定义索引与插件包下载都会走这个镜像；非 GitHub 托管的索引地址保持原样直连。留空则全部直连。

1. 下拉商店列表刷新索引；完成后会用提示条告知是否全部成功。
2. 列表每行是图标、插件名称与简介，点击进入独立详情页查看版本、分类、索引来源、源码仓库、许可证与项目主页；源码仓库和项目主页点击后用浏览器打开。
3. 在详情页点「安装」或「更新」，App 会从该插件的 GitHub Release 下载对应资产，读取包内 `plugin.json` 后展示真实权限与贡献，再确认安装。
4. 非官方插件每次安装、每次更新都要手动输入该插件的源码仓库地址；仓库归属 AiCode 官方 GitHub 账号的插件视为官方，不再要求手输。

索引只负责发现与版本信息，不代替安装包校验。下载失败、索引失联或版本不兼容时不会安装半成品。某个来源读取失败时会保留它上次成功读取的条目；缓存只影响展示，安装和更新仍会重新下载插件包并校验。

## 安装前先看这几点

- **AiCode 无法核验本地文件的来源。** 请只安装你信任的人提供的插件，弹窗里显示的「源码仓库」是插件自己写的，AiCode 不会去核实。
- **技能和子代理的内容会直接影响 AI 的行为。** 它们是一段段指令，名称和描述还会写进 AI 的系统提示词。装一个你没读过的插件，就等于让 AI 照着别人写的指令办事。
- **带运行时的插件会在容器里启动进程。** AI 工具与 hook 的逻辑在本地容器的子进程里运行，可以读写自己目录下的文件、安装 npm/pip 依赖、访问网络，与 Bash 同级。容器未初始化或缺少 node/python 时这类插件不可用；声明 `resident: true` 的插件会在 App 启动或首次调用后常驻，持续占用内存与容器资源。只安装你信任的插件。
- **工作区工具会把页面里的命令发到终端。** 这些命令在你点击运行后执行，安装前请确认你信任插件作者。
- **Shizuku 权限需要在插件详情中单独开启。** 插件声明用途后才会出现开关；开启后该插件可直接执行任意 Shizuku 命令。
- **插件页面可以读写文件和执行命令。** 插件自己的数据目录、工作区与 `.aicode` 目录都能经宿主桥访问；路径使用当前执行环境的真实路径，宿主会拦住 home、`~/.aicode`、工作区与插件安装/数据根的整体写入和删除。命令与 MCP 进程内部不受宿主路径限制，只安装你信任来源的插件。
- **插件可以读取会话、创建会话并发送消息。** 读取范围限当前工作区；发送的消息与手动输入走同一套 AI 轮次，会消耗 token，并照常弹出工具授权、受 PLAN/AUTO 模式约束。插件无法借此绕过审批。
- **运行 hooks 分只读、可写与代审核三种。** 只读 hook 只拿到运行标识、模式、状态、工具调用次数这类元数据，看不到消息正文、工具参数或结果；可写 hook 会在工具执行前拿到参数、在成功结束后拿到结果，能拒绝调用、改写参数或改写成功结果的数据，但不能替你批准工具，也不能绕过权限与 PLAN 模式。HTTP 请求 hook 还能看到并改写 URL、headers 与 body；敏感鉴权头在 hook payload 中只以 `{{Token}}` 占位符出现，宿主保留真实值。代审核 hook 能批准原本需要你确认的工具调用，包括 Shizuku、提权、配置修改、删除子代理与危险 rm；但不能覆盖宿主拒绝、PLAN 模式，也不能代审自己的工具。只安装你信任的插件。
- **MCP 插件会联网或启动进程。** HTTP 服务器会访问网络，stdio 服务器会在当前工作区的容器或 SSH 后端启动命令；只安装你信任的插件。
- 子代理的行为仍受当前模式约束（Plan 模式下只读），插件无法提升权限，也不能指定使用你的哪个供应商或模型——插件子代理一律沿用主会话的模型。

## 列表与详情

插件页底部有「已安装」和「插件商店」两个 tab；开启「开发者侧载」后会多出一个「开发中」tab（位于已安装右侧）。已安装页与商店页都支持下拉刷新；右上角依次是插件设置（第三方插件源、镜像加速、开发者侧载）和导入按钮。已安装列表每行左侧是方形图标，右侧上方插件名称、下方版本与作者标签，最右侧是启停开关和详情箭头；卸载入口在插件详情页右上角。

商店列表沿用同一版式，但右侧没有开关，第二行显示插件简介；点击任意一行进入独立详情页，安装、更新与版本要求都在详情页里。版本不足时，安装按钮会直接显示「要求 AiCode >= x.y.z」且不可点击。插件源码仓库不属于 AiCode 官方账号时，名称后面会显示「非官方」徽标。

已安装列表会结合最近一次读取的索引检查更新：有更高兼容版本时，名称后显示 `v旧版本 → v新版本`，版本/作者标签行多一个「可更新」标签。打开插件页时会自动读取索引；下拉已安装列表会同时刷新插件记录和索引。

「开发中」列表也与已安装一致：显示图标、名称、版本与安装状态标签、启停开关和箭头；已安装的侧载项目可以直接用开关启停，未安装的项目打开开关会进入安装预览；点击进入项目详情页，安装 / 重载在详情页完成。

| 开关状态 | 含义 |
| --- | --- |
| 开 | 插件运行正常，已授权的内容生效 |
| 关 | 插件已停用，它提供的内容全部不生效 |
| 开关不可用 | 插件文件丢失、被改动或与当前版本不兼容；请卸载后重新导入 |

点击列表项进入详情页。若插件声明了自身专属配置页面（`configPage`），顶部通过分段控件分为两个视图：

- **插件管理（系统固定配置）**：
  - **启用插件**：总开关；关闭后所有贡献和插件页面都不再生效；
  - **权限**：插件声明悬浮窗或 Shizuku 时出现，每项上方是权限名称、下方是插件声明的用途，右侧开关控制是否授权；浮层还要求系统已允许 AiCode 显示在其他应用上层，未开启时该项开关不可用；
  - **顶部信息卡与信息分组**：名称、简介、版本、发布者、许可证、源码仓库、来源（本地导入 / 索引仓库），样式与「设置 → 关于」一致；源码仓库一行点击后用浏览器打开；
  - **提供的内容**：按功能分类显示不同图标，每项展示名称和介绍；技能和子代理只显示本地名称（实际注册名仍带插件前缀）；插件停用时显示为半透明；
  - **卸载**：右上角的垃圾桶按钮，确认后删除插件及其授权记录；
- **插件配置（WebView 专属配置页面）**：
  - 展示插件包内自带的配置界面（用于填写 API Key、设置参数或个性化选项）；
  - 自动适配当前 App 的主题配色（背景、表面、字体、间距与圆角）、暗黑/浅色模式，与整个应用保持一致的视觉质感。

插件启用后，首次切到「插件配置」才会加载专属页面；停留在「插件管理」时不会提前执行配置页脚本。停用后只显示系统固定配置。停用、卸载或替换插件时，旧页面及其宿主接口会失效；重新启用后需重新打开页面。若插件未声明专属配置页面，则整屏直接展示系统固定配置。

插件页面可以订阅自己使用的文件变化，并在重新打开页面、App 回到前台或切换工作区时更新数据，不需要重启 App 或重新加载整个网页。这需要插件接入文件订阅和页面显示通知；已经安装的旧插件不会因此自动具备刷新逻辑。文件监听只在页面可见时运行，本地使用文件通知，SSH 使用按需快照检查；网络不可用时页面应保留已有内容。

## 在对话里怎么用

- **技能**：和普通技能一样，AI 会按需加载，你也可以在输入框用 `/` 菜单触发。插件技能的名字带着插件 ID 作前缀，形如 `community.demo-kit:project-notes`，所以不会和你自己建的技能重名。
- **子代理**：同样带前缀，AI 派发时用这个完整名字；也会出现在 AI 可派发的子代理清单里。
- **AI 工具**：出现在 AI 的工具清单里，名字形如 `plugin__community_demo-kit__echo`。首次调用会弹工具授权，确认后由容器内的插件进程执行并返回结果。
- **工作区工具**：在右侧项目工具抽屉的「全部工具」里添加，打开详情后由插件页面执行命令并展示输出。短命令走 `aicode.bash`；后台任务可用 `aicode.terminal` 创建共享标签，默认隐藏，需在「设置 → 终端设置 → 显示插件运行」开启后才在终端页可见。
- **槽位入口**：插件可以在设置页分组、侧栏底部、聊天顶栏菜单、空态建议、会话长按菜单、文件树长按和编辑器选区菜单注册入口。入口可以是 HTML 页面，或调用插件 runtime 的动作；文件树与编辑器只会展示动作。装好后出现在宿主固定位置，副标题标明插件来源。大屏下从侧栏、顶栏、会话菜单或文件树打开的页面进入右侧工作台。停用或卸载插件后入口消失。
- **输入框写入**：插件可通过页面 `aicode.chat.setDraft` 或进程 `host.chat.setDraft` 把文本写入当前会话输入框，支持追加；写完后用户仍可继续编辑再发送。
- **MCP 服务器**：插件启用后会自动连接，工具以 `mcp__plugin__…` 的形式出现在 AI 工具清单里；停用或卸载插件会断开连接并移除工具。
- **插件提供商**：启用后出现在设置 → 提供商和模型选择中，带「插件」标记。插件负责运行 OpenAI 兼容服务；宿主把地址注册成普通提供商条目，你可以像自建渠道一样改名、改地址、改凭据、启停，也可以从插件服务拉取并选择模型。插件也能在运行时维护自己声明条目的模型列表、模型上下文窗口与访问令牌（见插件开发文档的「插件提供商」一节）。停用或卸载插件后，该插件注册的条目会被删除。服务未就绪时请求失败，不会自动切到其他付费渠道。
- **远程会话**：支持远端执行的插件可以把历史消息推送到会话列表，并通过 OpenAI 兼容流实时显示正文和思考过程，使用 App 的流式动画；工具仍在远端执行，App 展示运行状态，不会再执行一次。重新打开正在运行的会话只恢复订阅，不会重发任务。停止按钮请求远端中断，离开会话不等于停止。
- **插件授权请求**：插件可以主动请求 App 显示授权卡片，卡片固定标注来源插件。你可以单次同意或拒绝，不会因此永久授权，也不会覆盖 App 已有的工具限制；插件停用、会话移除、切换工作区或超时后请求取消。
- **工具委托**：插件可以在工具真正执行前申请接管；App 仍按最终参数检查权限，通过后只由选定插件执行。委托失败不会自动改成本地执行，避免同一操作执行两次。
- **插件提示**：插件可以在对话里显示可关闭的提示条，最多同时排队 3 条；带按钮的提示点击后会回调插件自己的逻辑。
- **会话与消息**：插件可以读取当前工作区的会话和消息、创建新会话，并向会话发送一条用户消息。发送后就是一轮普通 AI 对话，会消耗 token，工具授权、PLAN/AUTO 模式、hooks 与队列行为都和手动输入一致；插件不能借此绕过审批。`sendMessage` 只表示请求已入队，不等待 AI 回复。
- **运行 hooks**：只读 hook 在 App 启动、插件安装/卸载/启用/停用、运行开始/结束、模型请求开始/结束、工具开始/结束与上下文压缩时收到通知，用来记录日志或统计，不影响这一轮的请求与结果；卸载与停用前的通知最多等待 10 秒，供插件清理自己的数据；可写 hook 在工具执行前拦截（可拒绝或改写参数，改写后重新走工具授权），在工具成功结束后改写结果数据，或每次 provider HTTP 请求前改写 URL、headers、body；HTTP hook 的敏感鉴权头以 `{{Token}}` 占位符提供，跨 origin 改写会剥离原始敏感头。所有可写 hook 失败、超时或格式不合法时保持原值继续，不会自动放行。代审核 hook 在 App 后台可自行弹浮层等待你同意或拒绝，单次最多等待 5 分钟；App 回到前台后应把请求交回应用内确认框。

「后台审批」示例插件在 App 后台显示一个小悬浮球；收到授权请求时，小球会原位平滑展开成审批卡片，同意或拒绝后再收回。多条请求会在同一张卡片中依次切换；也可以点卡片右上角收起，保留待审批角标，之后点小球继续处理。拖动小球或卡片标题栏可以移动位置。App 回到前台后，未处理的请求交回应用内确认框。

右侧项目工具抽屉可以从屏幕右半部分向左拖动拉开：拖动时跟随手指，松手后按拖动距离和速度吸附到打开或关闭；点遮罩或向右拖动可关闭。

`/` 菜单每次打开都会重新读取，新装、停用或卸载插件后马上可见。不过和普通技能一样，**AI 的可用技能清单在会话开始时生成，需要新开会话才会看到更新**；子代理清单则在下一轮对话就会刷新。

「设置 → 技能」和「设置 → 子代理」两个页面只列出你自己创建的内容，插件提供的内容请到「设置 → 插件」里查看。

## 更新与替换

开发者调试时可在「设置 → 插件」点右上角设置按钮，打开「开发者侧载」，把插件目录放到容器的 `~/.aicode/plugin-dev/<项目>/`（每个目录需含 `plugin.json`）。开启后底部会多出「开发中」tab，列出开发目录里的插件项目；点击项目进入详情页，点「安装」或「重载」即可。开启期间保存文件会自动重载，下拉该列表可重新扫描目录。该模式不参与在线更新，普通 `.zip` 导入仍然可用。打包会跳过 `node_modules`、`.git` 等目录，依赖请通过 `runtime.dependencies` 准备或预先 bundle。

再次导入一个**同 ID** 的插件包，就是替换安装：安装按钮会显示「替换安装」，继续会整体替换旧版本，并刷新该插件正在显示的悬浮窗，无需重启 App；同一个插件被重新打包过，即使内容没变，也会被当作不同的包。安装中断后会在下次加载时恢复到已保存的安装状态；卸载或清理旧包不会进入目录符号链接指向的其他目录。

在线安装的更新入口在「插件商店」：索引里的版本高于已安装版本时显示「更新」。非官方插件每次更新都要重新输入源码仓库地址；索引失联或下载失败时保留已安装版本。

## 和其他功能的关系

- **远程 SSH 模式**：插件和它的授权保存在手机上，切换到 SSH 模式不受影响，也不会被上传到服务器。
- **备份与还原**：插件暂时**不在**备份范围内，换手机或清除数据后需要重新导入。
- **工具授权**：插件的授权只决定「它的内容生不生效」，不会改变你在「工具授权」里对 AI 工具的任何设置。

## 出错怎么办

| 提示 | 怎么办 |
| --- | --- |
| 无法连接索引仓库 | 检查网络、第三方插件源或镜像加速地址；商店会保留上次成功读取的缓存，缓存只影响展示，不阻止安装或更新 |
| 安装按钮显示「要求 AiCode >= x.y.z」 | 索引里的 `min_app_version` 高于当前 App 版本；升级 AiCode，或让索引维护者调低该值。开发 / RC 构建按同一 `major.minor.patch` 的正式版比较；最低版本写成预发布时按完整版本比较 |
| 未找到可安装的插件版本 | 插件作者还没有发布对应版本的 `{id}_{version}.zip`，或索引里的版本与包内清单不一致；联系插件作者 |
| 这个文件不是有效的 ZIP 压缩包 | 确认选的是 `.zip`，并且没有下载一半；有些文件管理器会把 `.zip` 显示成其他类型，换一个文件管理器再试 |
| 压缩包根目录里没有 plugin.json | 打包时多套了一层目录，需要让 `plugin.json` 直接位于压缩包根部 |
| 此版本暂不支持的内容类型 / 字段 | 这个插件用了当前版本还没实现的功能（如提供商、新的 hook 事件）。等 AiCode 升级，或联系插件作者提供兼容版本 |
| 插件要求的插件接口版本不兼容 | 插件针对更新（或更旧）的 AiCode 编写，需要升级 AiCode 或更换插件版本 |
| 压缩包过大 / 文件过多 / 路径不安全 / 重复文件 | 包不符合安全限制，请联系插件作者；AiCode 不会放宽这些限制 |
| 其余「plugin.json 缺少/无效字段」「内容无效」「文件不存在」 | 都是插件包本身的问题，提示里会写明具体字段或文件，转给插件作者修复 |
