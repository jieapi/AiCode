# 工具授权 (Permissions)

进入“设置” -> “工具授权”，管理 AI 调用工具（Bash、writeFile 等）时保存的授权规则。

## 规则从哪来
*   对话中 AI 请求执行工具时会弹出授权弹窗：
    *   **始终允许**：在**当前项目**记住一条允许规则，之后按规则自动放行。规则按命令/路径精准匹配（如 `git pull`、`rm temp.log`）；命令含管道 / 重定向 / 命令替换等无法记住，只能单次放行。
    *   **拒绝**：只拒绝本次调用，不产生规则。
*   系统内置安全白名单：少量完全无害、只读且不派生子进程的命令（如 ls、pwd、cat、grep、ps、top、git status 等）免弹窗自动放行。

## 页面结构
*   **工具审批开关**：页面顶部分组，列出需要审批的工具（Bash、terminal、writeFile、editFile、task、MCP 工具）：
    *   开关**开启**（默认）：该工具调用时需弹窗审批。
    *   开关**关闭**：该工具自动放行，不再弹窗；但配置的「禁止」（deny）规则仍生效，AUTO/PLAN 模式判定不受影响。
*   **git 命令审批**：git 写命令按子命令分组开关（commit / push / pull / 分支标签 / 其它写操作），关闭对应开关则该类命令自动放行；git 只读命令（status/log/diff 等）始终自动放行。
*   **当前项目 / 全局**两个分组，点击分组标题可折叠 / 展开（右侧箭头指示方向），规则较多时方便查看另一组。
*   每条规则显示：判定图标（对勾 = 允许 / 叉 = 禁止）、工具名、匹配范围与判定（如 `git pull · 允许`、`整个工具 · 允许`）。
*   项目规则右侧的「提升为全局」图标（地球）可将该规则复制为全局规则，对所有项目生效；操作后本项目内该规则消失。
*   规则行**左滑**露出红色「删除」按钮，点击删除该规则。

## 关于「禁止」规则
*   授权弹窗没有「禁止」选项（拒绝只影响单次），正常使用不会产生禁止规则。
*   `deny` 列表目前只能手动编辑配置文件产生：项目规则写在 `<项目根>/.aicode/permissions.json`，全局规则写在 App 私有目录 `~/.aicode/permissions.json`。手动编辑保存后，App 会在数秒内自动检测并刷新「工具授权」页列表，评估规则即时生效。
*   安全设计：**全局禁止优先于项目允许**——`deny` 里的规则会挡掉同名 `allow` 规则（如全局禁止 `Bash(rm -rf /)` 后，任何项目都不能放行该命令）。

配置文件格式示例：

```json
{
  "permissions": {
    "allow": ["Bash(git pull)", "writeFile"],
    "deny": ["Bash(rm -rf /)"]
  }
}
```
