# 插件系统计划：实施路线、验收与待确认决策

状态：规划与决策记录。2026-11-12 已收敛主要边界；剩余待定见第 5 节。

## 0. 交付分层

下面 7 个阶段把全部价值压在“JS 运行时可行性验证”这一个前置上。若验证失败，整套计划都会停住。因此按**是否需要执行第三方代码**把交付分成两层，第 0 层不依赖引擎结论，可以先落地并独立发布。

| 层 | 内容 | 是否需要 JS 运行时 | 状态 |
| --- | --- | --- | --- |
| 第 0 层：声明式贡献 | 技能、子代理（已实现）；MCP 配置来源；提示词片段来源；语法 / 主题包；设置里声明式配置的用户 Hook（命令走现有 Bash 后端） | 否 | 前两项已实现 |
| 第 1 层：运行时贡献 | 工具、HTML 页面与配置、hooks、代审核、提供商、服务环境、通知 / tips / Shizuku 的插件侧调用 | 是 | 部分实现 |

第 0 层的各项仍要遵守同一套身份、授权、命名空间和撤权规则；它们没有“少一点安全”的捷径，只是不需要沙箱就能满足。

几个值得优先评估的第 0 层项（均基于已核实的现有代码）：

- **声明式用户 Hook**：现有代码里没有任何用户可配置的 hook。常见用途是 AI 改完文件后自动格式化 / 类型检查，以及任务结束通知。命令在使用者自己的配置里，权限模型最简单；事件目录可与后续插件 hooks 共用。
- **提示词片段作为插件来源**：四级解析（项目 > 全局 > 本地 > 内置）已存在，插件作为新层需要先定优先级。已核实 `.no-builtin` 只在全局层被识别（`PromptFragmentCatalog` 与 `SystemPromptProvider` 都只检查全局 `prompts.custom/`），项目层放这个文件不生效。
- **语法 / 主题包**：`TextMateSetup` 只注册 `AssetsFileResolver`，主题硬编码，需要新增文件系统解析。已知缺口：groovy、ini、toml、dockerfile、makefile、sql、scss 目前按纯文本显示。
- **UI 扩展点**：消息操作菜单的四项（编辑 / 复制 / 分叉 / 删除）是 `MessageActionsBottomSheet` 的固定参数，已核实；文件树长按菜单与编辑器顶栏按钮同样是写死的，这两处来自代码探索报告，尚未逐行复核。需要先新增数据驱动的贡献点，插件才能挂入。

## 1. 阶段划分

阶段体现依赖关系，不表示自行缩减用户要求。构建插件的页面/配置形态、声明加绑定、命令目标与范围内直接执行已确认；提供商插件对接 App 当前接口，上游由插件处理。具体协议和生命周期仍需细化，不给没有依据的工期估算。

源码目录、发布包目录、插件清单和索引格式的具体草案已补入 [10-plugin-format.md](10-plugin-format.md) 与 [11-index-format.md](11-index-format.md)，包含字段、引用规则及完整 JSON 样本。它们覆盖提供商等贡献，仍需审阅定稿，不等于已实现 SDK、完整 UI 协议或实际可安装产物。

### 阶段 0：补齐产品与安全定义

- 审阅已给出的源码/发布包/清单及索引文件结构、字段和示例，统一容纳工具、MCP、Skill、子代理、提供商和页面等贡献；明确哪些草案字段定稿、哪些仍需验证。
- 细化通用 UI 的布局/样式语义、绑定、表单、事件和现有 DIY 的协议演进方式。
- 确认右抽屉打开后的内容容器、配置保存作用域，以及关闭页面/切换环境时的任务行为。
- 确认 hook 的可读字段、允许改写的内容，以及一次请求/一次运行的边界。
- 按已确认的顺序首个决定、只拒绝当前工具规则，细化异常/超时、特殊高危请求和授权范围。
- 确认 Shizuku 接口形式、授权持续性和逐次确认要求。
- 细化 Bash/terminal 的授权范围、任务/终端归属、取消和执行上下文；不重新询问已确认的范围内直接执行规则。
- 确认插件安装/启用作用域和主动模态交互；设置内管理入口、多索引与在线安装更新已确认，不重复询问。
- 确定官方身份的认定方案，以及源码仓库地址的等价形式与输入规则；非官方每次安装/更新都手输的要求不再列为未定。

**退出条件**：这些决定能对应到具体场景与验收结果，而不是仅用“支持 hook”“支持权限”概括；未决定项有明确阻塞关系。

### 阶段 1：运行时与 UI 协议可行性验证

- 在候选运行时验证 JS/异步宿主调用、取消、内存/CPU/返回值边界和崩溃恢复。
- 覆盖最低系统与两类 ABI，确定不支持设备的行为。
- 确定语言、引擎、隔离单元和资源预算；验证失败则重新选型，不静默降级安全边界。
- 形成宿主消息协议、SDK 基本类型、身份绑定与取消语义。
- 已定：HTML 页面 + 页面桥，不再验证声明式 UI；表单焦点与响应式布局由页面自行负责。

**退出条件**：宿主能承受恶意循环、OOM 和畸形消息；UI 更新不靠重复执行命令；每项安全承诺有实际验证，运行时及许可证/构建影响经过确认。

### 阶段 2：插件包、管理和能力授权

- 明确通用清单、插件 API / UI 协议兼容性、页面/配置引用和包校验规则，区分安装元数据与具体 UI 声明。
- 建立“设置 → 插件”的宿主管理入口和名称/版本列表，提供配置、权限及安装/启停/更新/卸载等管理接入与基础诊断。
- 建立插件独立授权、作用域、撤权、过期回包处理；授权状态不能经插件文件接口篡改。
- 界面明确区分插件权限、工具审批、系统权限和高风险外部执行。
- 实现已确认的手动服务依赖准备入口与状态：environments 声明、锁定输入、独立环境、前置检查和 environment.prepare；缺解释器报告，不自动装系统工具。

**退出条件**：启用状态、身份与归属正确；安装/更新失败保持一致状态，身份变化不能继承安装状态。

### 阶段 3：HTML 页面与页面桥（已完成方向）

- 页面统一为 HTML/CSS/JS，由 WebView 加载；宿主提供页面桥、Vue 组件库与主题变量。
- 配置页、设置页入口与工作区工具共用同一套 WebView 容器与桥。
- 页面自行处理布局、状态与表单；宿主不解析 UI 声明，不代插件重绘。
- 验证手机/平板、主题、字体缩放、键盘遮挡、长列表与页面资源边界。
- WebView 缓存按插件版本失效；停用/卸载后入口消失。

**退出条件**：三类页面共用同一容器与桥，不复制多套渲染器；加载页面不触发构建/下载等业务副作用。

### 阶段 4：工具、内容与提供商贡献接入

- 工具：可信适配器、参数 schema、宿主风险分类、工具名与归属、取消及结果边界。
- MCP：复用现有协议与传输，增加插件来源和连接/进程启动前的授权；保留既有手工配置行为。
- Skill：手机端插件来源、清单与正文一致、禁用与缓存失效、脚本资源策略。
- 子代理：复用定义与派发，验证父会话限制、来源、版本和在途定义行为。
- 提供商：插件提供 OpenAI 兼容接口，上游转换由插件实现；增加归属、失效和凭据边界，不在 App 新增插件专用上游适配器。
- 对停用/更新时已被模型列出的贡献，设计清晰的执行拒绝或版本快照策略。

**退出条件**：工具、MCP、Skill、子代理、提供商均可真实使用并按归属停用/卸载；不能覆盖或删除其他来源。插件兼容服务在本地/SSH 场景可达，失效不静默切换到其他付费渠道。

### 阶段 5：右抽屉页面、配置与受控命令

- 增加右侧插件列表和页面导航，与现有会话侧栏、大屏工作台及返回行为协调。
- 插件提供 UI 声明和业务 handler，设置内插件配置入口使用同一结构化引擎；插件权限页由宿主提供。
- 复用与 AI 一致的 CommandEngine / TerminalSessionProvider，增加插件身份、授权检查、任务归属和类型化结果/事件；共享标签可在用户终端页查看和交互。
- 命令发送使用新建共享标签；接通打开/聚焦插件已有任务的宿主入口，避免导航重复执行命令或无条件 toggle 关闭终端。自动打开/抢焦点待定，不增加接管已有用户标签的功能。
- 插件逻辑在手机，命令跟随工作区；任务后续操作绑定原后端，避免切换环境后误路由。
- 获授权范围内直接执行命令，不逐条弹窗；保留 AI 来源限制和特殊操作边界。
- 验证构建与依赖下载由插件完成，宿主没有新增特定框架的命令、源或构建步骤分支。

**退出条件**：插件页面和配置可交互、反馈进度/日志/错误；任务不因重组重复执行，非零退出不误报成功；其他插件和用户终端不被越权读取或操作。

### 阶段 6：生命周期、代审核与双向交互

已实现部分：只读 hooks、工具前后与 HTTP 请求可写 hooks、全部 ASK 代审核（`agent.permission.review`，含高危）。

- 落实已确认的请求前、完成时等生命周期扩展需求；阶段 0 确认具体事件目录和可读/可变字段后，按定稿接口派发，保证关联、顺序和终态。
- 在宿主 ASK 分支接入代审核三态流程，保留无插件和不处理时的原有 UI。
- 实现已确认的多插件顺序首个决定和仅拒绝当前工具规则；异常/超时、撤权细节和建议的审批来源记录，先在阶段 0 确认后再实现。
- 实现 tips、交互回调、插件通知和 Shizuku 宿主接口。
- 单独验证高权限能力、回调重入、多个会话并发和插件运行时死亡。

**退出条件**：端到端场景能验证“宿主先判断、插件后代审、未处理回 UI”；参数不可能在获批后被静默替换；插件异常不能自动批准。

### 阶段 7：目录分发、发布与安全验收

- 落实可配置多索引仓库、仅存索引、每插件独立源码仓库的方案，完成来源聚合、冲突与缓存隔离。
- 按阶段 0 确认的规则展示官方状态，不把被收录或自报字段当成未经核验的官方身份。
- 完成在线安装更新：非官方每次均有宿主弹窗并手输该插件源码仓库地址；取消或不匹配不得应用。
- 完成增权确认、风险撤回和离线行为，不提供绕过非官方逐次确认的无交互更新路径。
- 发布开发者 SDK 文档、示例与契约测试；同步 App 使用说明、提示词和双语资源。
- 完成回归、安全评审和真机 RC 验证，再考虑正式发布。

**退出条件**：实现功能与本计划逐项对应；没有通过额外依赖安装或宽泛权限掩盖未完成能力；发布和密钥权限分离。

## 2. 建议的验收矩阵

| 场景 | 预期 |
| --- | --- |
| 未声明或未授予通知/Shizuku/代审核权限 | 宿主拒绝，不因 App 已有系统授权或 AUTO 模式放行 |
| 声明并授权的能力被撤销 | 新调用与尚未执行的旧批准失效，已发生副作用不伪称回滚 |
| 宿主直接放行或拒绝的 AI 调用 | 不进入代审核插件 |
| 宿主需要确认，插件同意 | 仅批准匹配的本次调用，记录来源，不新增永久规则 |
| 插件不处理、无适用插件、失联或超时 | 不处理继续下一个；无人决定才到 UI，异常按定稿策略处理，不自动批准 |
| 插件拒绝批次中的一个调用 | 仅该工具返回拒绝，其余继续审批执行；结果配对完整，AI 可以继续 |
| 同一结构化基础用于 DIY、插件页面和配置 | 共享解析/校验与渲染，宿主场景约束分别明确 |
| 表单、动态列表、条件与进度状态变化 | 焦点/节点身份稳定，不重建整页、不重复发起业务 |
| 窄屏、平板分栏、主题、键盘与长日志 | 布局可用、性能有界，不能只用固定截图验收 |
| 获授权插件从 UI 调用 Bash/terminal | 范围内直接执行，不逐条确认；越权和撤权不放行 |
| 插件命令在本地/SSH 模式运行 | 后端跟随启动时工作区，运行句柄不因切换而指向其他目标 |
| 插件终端读取/输入/关闭 | 仅操作获授权且有归属的句柄，不默认列出全部用户终端 |
| 插件任务进入用户终端页面 | 复用共享后端和标签，打开/聚焦已有任务不重新执行；用户可查看和交互 |
| 设置 → 插件列表 | 名称、版本等信息可见，配置进入结构化内容，权限进入宿主可信管理页 |
| 多索引出现同名或同 ID 条目 | 显示来源与冲突，不错装、不自动换源或污染缓存 |
| 非官方首次安装和每次更新 | 均有宿主确认弹窗并手输插件源码仓库地址，取消/不匹配不继续 |
| 版本、来源或包内容在确认期间变化 | 旧确认失效，重新显示目标；手输来源不替代增权授权 |
| 索引自称某插件是官方 | 按最终定稿的身份规则核验，不凭任意字段跳过手输步骤 |
| 构建、下载依赖或安装上游脚本 | 由插件提供业务与风险说明，App 只提供授权后的通用执行能力 |
| 页面重组、返回、关闭或插件更新 | 不重复执行任务；按定稿生命周期处理，旧回包不写入新页面 |
| 多插件可能给出不同结论 | 按使用者顺序，首个同意/拒绝生效，后续不再询问 |
| 审批期间修改参数、工具版本、项目或模式 | 旧结果无效，重新校验，必要时重新审核 |
| 审批期间撤权、停用、更新或会话删除 | 旧回包不再生效，不操作新会话或新版插件 |
| 多个会话/子代理同时请求审批 | 数据和决定不串会话，慢插件不持有全局锁 |
| 无限循环、内存耗尽、超大消息 | 有资源边界，宿主可恢复，不降级到不安全运行方式 |
| 注册同名工具/Skill/子代理/MCP | 不覆盖其他来源，归属和模型工具名稳定 |
| 连接插件 stdio MCP | 启动前取得对应授权，明确不属于 JS 沙箱 |
| Skill 引用脚本，切到 SSH | 行为符合已定资源策略，不假定服务器存在手机路径 |
| 请求前 hook 修改输入 | 校验预算、压缩和协议配对，落库与模型实际输入的关系明确 |
| 请求网络重试或换 Key | 不重复执行业务副作用，不暴露 Key 原文 |
| 完成、失败、取消、外层初始化异常 | 终态区分正确，受控路径去重，不把 Completed 等同于成功 |
| tips/通知点击到达已卸载或更新的插件 | 不唤醒旧代码，不继承过期授权 |
| 通知被系统关闭、Shizuku 未运行或失去授权 | 明确报告不可用，不伪造成功，不代用户批准系统授权 |
| 恶意包、压缩炸弹、路径越界或身份替换 | 在资源边界内拒绝，现有版本和其他插件不受影响 |
| 下载失败、权限扩大或目录风险撤回 | 不启用未验证/未授权的新版本，按明确策略提示或停用 |
| 提供商插件连接非内置协议上游 | 插件输出 App 当前兼容接口，App 不新增该上游适配器即可完成调用 |
| 插件提供商服务未就绪、失联或停用 | 明确标识不可用，不错用旧地址，不静默回退其他付费上游 |
| 插件提供商配置/模型测试/实际请求 | 归属、版本和入口一致，仅使用该插件获授权的配置与凭据 |
| 服务依赖未准备/缺前置工具 | 显示原因并阻止相关服务，仍可管理/配置插件，不自动安装系统工具 |
| 用户点击准备环境 | 核对授权/目标/锁定输入，日志可见；失败/取消不标 ready |
| 准备中切换工作区或更新插件 | 旧任务仍绑定原目标，旧结果不覆盖新版本/目标状态 |
| 索引/清单/锁文件不一致 | 拒绝旧确认，不改锁、换源或降版本绕过 |
| 未安装插件/全部停用 | AI、工具审核、MCP、Skill、子代理、用户提供商和通知保留原有工作流 |

测试覆盖单元、接口契约、宿主集成和真机。JS 沙箱、系统通知、Shizuku、PRoot 和进程终止不能只靠 JVM mock 测试宣称通过。

## 3. 实施阶段的项目验证要求

本轮没有改编译型代码，因此不运行 Gradle 构建或单测。实施后按项目规则执行：

- 编译型代码改动：`./gradlew :app:assembleUniversalDebug`。
- 推送前：`./gradlew :app:testUniversalDebugUnitTest` 与 `python3 scripts/check_migrations.py`。
- 如选择 Room 保存插件状态，遵守实施时真实 schema 版本与迁移编号，不预占本轮迁移号。
- UI 文案入中英 `strings.xml`；AI 工具与行为同步 `app/src/main/assets/prompts/`；面向使用者的功能说明同步 `docs-site/docs/`。
