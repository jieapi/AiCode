# 插件系统计划：设置内的插件管理

状态：讨论稿。设置入口、插件列表信息、配置/权限操作、多索引仓库和在线安装更新已确认；具体排版及官方身份认定尚未定稿。

## 1. 两个入口的职责

```text
设置 → 插件
  → 插件管理列表：名称、版本等信息
  → 插件配置 / 插件权限 / 其他管理操作
  → 索引仓库配置、在线安装与更新入口

右抽屉 → 选择插件
  → 插件声明的功能 UI
  → 构建、下载依赖等插件业务
```

**已确认**：设置中的插件入口负责管理，右抽屉负责打开功能；两者可以引用同一插件身份，但不能把配置页和业务页面当成同一个入口。

建议插件管理、权限和安装确认使用宿主可信 UI；只有插件自己的业务页面与配置内容由结构化声明提供。插件不能覆盖宿主身份区、操作按钮或权限结论。

## 2. 插件管理列表

用户已确认列表显示插件名称、版本等信息，并提供插件配置、插件权限等操作。

建议默认呈现已安装插件，并提供在线安装和索引管理入口；是否采用标签页、分组或独立二级页待 UI 细化，不在本轮锁定。

| 信息 | 当前状态 | 说明 |
| --- | --- | --- |
| 插件名称、已安装版本 | 已确认 | 使用者能识别当前安装内容 |
| 是否官方 | 已确认要展示 | 认定规则待确认，不能只相信第三方声明 |
| 来源、作者、独立仓库 | 建议 | 区分同名条目和不同发布者，能查看确切来源 |
| 启停/异常状态 | 建议 | 避免已停用、不可用仍被误认为在运行 |
| 可用更新版本 | 在线更新所需 | 与已安装版本分开，不用远端最新版本覆盖本地显示 |

未安装的在线条目要显示真实状态，不假装已经启用；拉取索引或检查更新失败也不能清空已安装列表。

## 3. 管理操作

| 操作 | 职责 | 当前状态 |
| --- | --- | --- |
| 插件配置 | 打开插件声明的结构化配置页 | 已确认 |
| 插件权限 | 打开宿主权限管理，查看申请、已授予与撤销情况 | 已确认 |
| 在线安装 / 更新 | 进入宿主来源确认、校验与权限变化流程 | 已确认 |
| 准备环境 | 用户手动准备已声明、已授权的插件服务依赖，展示检查/日志/结果 | 已确认 |
| 启用 / 停用、卸载 | 管理插件生命周期，不误删其他来源贡献 | 延续已有计划，具体按钮布局建议待定 |
| 查看来源 / 错误 | 查看仓库、版本和诊断信息 | 建议 |

没有配置声明的插件不能用空白页或错误页面伪装有配置。具体是隐藏配置操作还是置灰并解释，待定。

“操作按钮”不等于本轮已决定所有操作都排成一行；行内按钮、操作菜单或详情页的分配仍需适配窄屏与大屏。

## 4. 插件配置页

入口为“设置 → 插件 → 对应插件 → 插件配置”。配置内容使用 [06-structured-ui.md](06-structured-ui.md) 的声明、表单、状态绑定和事件机制。

- 宿主固定显示正在配置的插件身份与版本，结构化内容不能伪装成另一个插件或宿主设置。
- 插件定义业务字段、校验和配置 handler，宿主提供限定作用域的读取/保存接口。
- 配置值写入不等于授权，配置中的“允许执行命令”等开关不能直接修改宿主权限记录。
- 全局/项目作用域、自动保存/显式保存、敏感字段和配置迁移继续待确认。
- 插件错误、页面销毁或版本更新后，旧回调不能写入另一个版本或项目的配置。
- 打开配置页不自动执行构建、安装依赖或获得新能力；确有业务副作用的动作仍走能力授权。
- 提供商插件也可以通过此配置入口收集自身上游配置；注册后的供应商实例、模型选择仍接入现有提供商流程，并显示插件归属。配置入口不使其获得其他渠道凭据，见 [09-provider-plugins.md](09-provider-plugins.md)。

## 5. 插件权限页

这是宿主可信管理界面，不由插件声明整页替代。应能区分：

- 插件清单申请了哪些能力、用途和范围。
- 使用者已经授予什么、哪些未授予或已被撤销。
- 当前系统/后端是否可用，例如通知开关、Shizuku 状态、容器或 SSH 就绪状态。
- 服务依赖环境是否未准备、缺少前置工具、准备中、ready 或失败；用户可点击准备/重试，不能因普通页面渲染就自动安装。
- 哪些权限在更新版本中增加或扩大，尚待使用者批准。

已确认 Bash/terminal 获授权范围内直接执行，不能在权限页授权后又默认逐命令弹窗。通知、代审核、Shizuku 等能力分别管理，不能用一个“信任此插件”自动授予全部。

权限变更应影响后续调用和待执行的旧授权；对已经启动的命令，停止/等待策略仍须明确。UI 可以让用户操作所有插件的权限，但插件 SDK 不能因此获得跨插件管理能力。

服务依赖准备独立于插件包安装；环境未就绪时保留配置、权限、卸载和诊断操作，仅阻止依赖它的服务。缺少解释器报告缺项，不在准备按钮后偷偷安装系统工具，详见 [12-service-dependencies.md](12-service-dependencies.md)。

## 6. 索引仓库配置

设置内插件管理提供多索引配置入口；具体是列表页按钮还是二级项待定。

建议每个来源展示：名称、索引仓库地址、启用状态、刷新结果和来源身份。可配置多个来源是已确认能力，不再作为可选扩展。

- 新增/编辑地址要明确这是索引来源，不是插件独立源码仓库或下载链接。
- 普通索引不能靠设置一个显示名称就成为 AiCode 官方信任根。
- 来源失联时分别报告，不影响其他来源；已安装插件保留来源记录。
- 删除索引不应无提示改变插件的更新源；是否保留条目的离线信息或允许手工迁源需再定义。
- 索引认证、私有源、本地索引等未确认，不擅自加入凭据界面或其他传输类型。

来源聚合、冲突和缓存策略见 [04-distribution.md](04-distribution.md)。

## 7. 在线安装和更新的 UI 行为

**已确认**：非官方插件每次安装和每次更新，都弹出宿主确认界面，要求输入该插件的源码仓库地址。它不是输入索引地址，也不是首次确认后永久免除。

界面至少区分所选插件、版本、源码仓库、索引来源、下载/校验状态和权限变化。输入不匹配或取消时不继续安装，地址确认和能力授权也不能相互替代。

官方标识的认定规则仍待确认。建议区分“官方维护”和“来自官方索引”，不要让第三方索引伪造官方身份绕过手输门槛；在无法核实身份时不据其自称跳过确认。

在线更新不等于无交互自动更新；可以检查并提示可用版本，但非官方每次真正应用更新都保留确认步骤。后台检查、官方自动应用和批量更新的呈现方式尚未决定。

## 8. 终端联动

构建插件复用 AI 的 Bash/terminal 通用执行后端，通过新建共享标签在用户终端页面查看和交互，不接管已有用户标签，也不创建与用户终端完全割裂的私有终端系统。

插件拥有受控句柄，宿主 UI 仍可以展示和由使用者管理这些标签。插件在终端页可见，不意味着它可以读取或操作所有用户标签；具体的标签聚焦、页面导航与归属见 [07-build-plugins.md](07-build-plugins.md)。

## 9. 现有项目接入依据

- 设置分区定义在 [SettingsScreen.kt:147](../../app/src/main/java/com/aicode/feature/settings/presentation/component/SettingsScreen.kt:147)，层级与返回方向在 [SettingsScreen.kt:183](../../app/src/main/java/com/aicode/feature/settings/presentation/component/SettingsScreen.kt:183)，设置菜单在 [SettingsScreen.kt:1627](../../app/src/main/java/com/aicode/feature/settings/presentation/component/SettingsScreen.kt:1627)。应复用现有设置导航和大屏行为，不另起一套不兼容设置壳。
- 设置入口、列表行、表单、开关和模态容器继续遵守项目的 `SettingsGroup` / `SettingsRow`、`AppTextField`、`AppSwitch` 和 `AdaptiveModalBottomSheet` 约定。
- 宿主新增文案进入中英资源，功能说明同步使用文档；插件自己的业务文案/本地化协议另行定义，不在宿主硬编码具体插件内容。

## 10. 建议验收

- 从设置打开插件列表，名称和版本可见，配置与权限操作定位到正确的插件。
- 配置内容使用通用结构化引擎，权限、身份和安装确认仍由宿主掌控。
- 多索引可分别刷新，冲突和失联不导致错装、换源或丢失已安装状态。
- 非官方首次安装和每次更新都要求正确源码地址，取消/输入错误不能继续，代审核插件不能代填代批。
- 官方标识按最终确认的规则计算，不因为任意索引自报而绕过额外确认。
- 插件终端任务可以在用户终端中找到和操作，而插件仍不能访问其他归属标签。
