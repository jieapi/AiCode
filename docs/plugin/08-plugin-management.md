# 插件系统计划：设置内的插件管理

状态：部分实现。设置入口、插件列表、配置页与启停已实现；权限页取消，改为安装确认与能力展示；在线索引本轮不做；官方标识用官方索引地址白名单。

## 1. 两个入口的职责

```text
设置 → 插件
  → 插件管理列表：名称、版本等信息
  → 插件配置 / 安装信息 / 启停与卸载
  → 索引仓库配置、在线安装与更新入口（本轮不做）

右抽屉 → 选择插件
  → 插件自带的 HTML 页面
  → 构建、下载依赖等插件业务
```

**已确认**：设置中的插件入口负责管理，右抽屉负责打开功能；两者可以引用同一插件身份，但不能把配置页和业务页面当成同一个入口。

插件管理、安装确认使用宿主可信 UI；插件自己的业务页面与配置页是 HTML，由 WebView 加载。插件不能覆盖宿主身份区、操作按钮或安装结论。

## 2. 插件管理列表

列表显示插件名称、版本等信息，并提供插件配置、安装信息、启停与卸载操作。

建议默认呈现已安装插件，并提供在线安装和索引管理入口；是否采用标签页、分组或独立二级页待 UI 细化，不在本轮锁定。

| 信息 | 当前状态 | 说明 |
| --- | --- | --- |
| 插件名称、已安装版本 | 已确认 | 使用者能识别当前安装内容 |
| 是否官方 | 已确认要展示 | 官方索引地址白名单；自定义索引一律非官方 |
| 来源、作者、独立仓库 | 建议 | 区分同名条目和不同发布者，能查看确切来源 |
| 启停/异常状态 | 建议 | 避免已停用、不可用仍被误认为在运行 |
| 可用更新版本 | 本轮不做 | 在线索引上线后再补，不用远端最新版本覆盖本地显示 |

未安装的在线条目要显示真实状态，不假装已经启用；拉取索引或检查更新失败也不能清空已安装列表。

## 3. 管理操作

| 操作 | 职责 | 当前状态 |
| --- | --- | --- |
| 插件配置 | 打开插件的 HTML 配置页 | 已实现 |
| 安装信息 | 展示来源、版本、贡献与高危能力 | 已实现 |
| 在线安装 / 更新 | 进入宿主来源确认、校验与能力变化流程 | 本轮不做 |
| 准备环境 | 用户手动准备插件声明的服务依赖，展示检查/日志/结果 | 已实现（依赖准备） |
| 启用 / 停用、卸载 | 管理插件生命周期，不误删其他来源贡献 | 已实现 |
| 查看来源 / 错误 | 查看仓库、版本和诊断信息 | 建议 |

没有配置声明的插件不能用空白页或错误页面伪装有配置。具体是隐藏配置操作还是置灰并解释，待定。

“操作按钮”不等于本轮已决定所有操作都排成一行；行内按钮、操作菜单或详情页的分配仍需适配窄屏与大屏。

## 4. 插件配置页

入口为“设置 → 插件 → 对应插件 → 插件配置”。配置页是包内 HTML，通过页面桥读写数据；宿主只提供 WebView 容器与主题，见 [06-structured-ui.md](06-structured-ui.md)。

- 宿主固定显示正在配置的插件身份与版本，插件页面不能伪装成另一个插件或宿主设置。
- 插件定义业务字段、校验与保存时机，通常写插件数据目录或工作区 `.aicode`；宿主不解析字段。
- 配置值写入不改变插件启停或宿主状态；配置中的“允许执行命令”等开关只是插件自己的设置。
- 插件错误、页面销毁或版本更新后，旧回调不能写入另一个版本或项目的配置。
- 打开配置页不自动执行构建、安装依赖或获得新能力；确有业务副作用的动作仍由插件在启用范围内执行。
- 提供商插件也可以通过此配置入口收集自身上游配置；注册后的供应商实例、模型选择仍接入现有提供商流程，并显示插件归属。配置入口不使其获得其他渠道凭据，见 [09-provider-plugins.md](09-provider-plugins.md)。

## 5. 安装信息与能力展示

这是宿主可信管理界面，不由插件页面替代。应展示：

- 插件声明的贡献与能力，包括可写 hook、HTTP hook、代审核与 Shizuku。
- 当前系统/后端是否可用，例如通知开关、Shizuku 状态、容器或 SSH 就绪状态。
- 服务依赖环境是否未准备、缺少前置工具、准备中、ready 或失败；用户可点击准备/重试，不能因普通页面渲染就自动安装。
- 更新后新增的高危能力，安装确认时再次提示。

Bash/terminal、通知、代审核、Shizuku 等能力随插件启用生效；安装确认展示这些能力与风险，不再逐项管理。

停用或卸载应影响后续调用与待执行审批；对已经启动的命令，停止/等待策略仍须明确。UI 可以让用户管理所有插件，但插件 SDK 不能因此获得跨插件管理能力。

服务依赖准备独立于插件包安装；环境未就绪时保留配置、卸载和诊断操作，仅阻止依赖它的服务。缺少解释器报告缺项，不在准备按钮后偷偷安装系统工具，详见 [12-service-dependencies.md](12-service-dependencies.md)。

## 6. 索引仓库配置

设置内插件管理提供多索引配置入口；具体是列表页按钮还是二级项待定。

建议每个来源展示：名称、索引仓库地址、启用状态、刷新结果和来源身份。可配置多个来源是已确认能力，不再作为可选扩展。

- 新增/编辑地址要明确这是索引来源，不是插件独立源码仓库或下载链接。
- 普通索引不能靠设置一个显示名称就成为 AiCode 官方信任根。
- 来源失联时分别报告，不影响其他来源；已安装插件保留来源记录。
- 删除索引不应无提示改变插件的更新源；是否保留条目的离线信息或允许手工迁源需再定义。
- 索引认证、私有源、本地索引等未确认，不擅自加入凭据界面或其他传输类型。

来源聚合、冲突和缓存策略见 [04-distribution.md](04-distribution.md)。

## 7. 在线安装和更新的 UI 行为

**已确认**：非官方插件每次安装和每次更新，都弹出宿主确认界面，要求输入该插件的源码仓库地址。它不是输入索引地址，也不是首次确认后永久免除。

界面至少区分所选插件、版本、源码仓库、索引来源、下载/校验状态和能力变化。输入不匹配或取消时不继续安装，地址确认和能力展示也不能相互替代。

官方标识按官方索引地址白名单：只有内置或官方维护的索引来源标官方，自定义索引一律非官方；不据第三方自报跳过手输确认。

在线索引与更新本轮不做；后续可以检查并提示可用版本，但非官方每次真正应用更新都保留确认步骤。

## 8. 终端联动

构建插件复用 AI 的 Bash/terminal 通用执行后端，通过新建共享标签在用户终端页面查看和交互，不接管已有用户标签，也不创建与用户终端完全割裂的私有终端系统。

插件拥有受控句柄，宿主 UI 仍可以展示和由使用者管理这些标签。插件在终端页可见，不意味着它可以读取或操作所有用户标签；具体的标签聚焦、页面导航与归属见 [07-build-plugins.md](07-build-plugins.md)。

- 宿主新增文案进入中英资源，功能说明同步使用文档；插件自己的业务文案/本地化协议另行定义，不在宿主硬编码具体插件内容。

## 10. 建议验收

- 从设置打开插件列表，名称和版本可见，配置与安装信息操作定位到正确的插件。
- 配置页使用 HTML，身份与安装确认仍由宿主掌控。
- 本轮不做在线索引；后续多索引可分别刷新，冲突和失联不导致错装、换源或丢失已安装状态。
- 后续非官方首次安装和每次更新都要求正确源码地址，取消/输入错误不能继续，代审核插件不能代填代批。
- 官方标识按官方索引地址白名单计算，不因为任意索引自报而绕过额外确认。
- 插件终端任务可以在用户终端中找到和操作，而插件仍不能访问其他归属标签。
